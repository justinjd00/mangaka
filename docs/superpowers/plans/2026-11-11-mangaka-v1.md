# mangaka v1 implementation plan

**Spec:** `docs/superpowers/specs/2026-11-11-mangaka-design.md` (binding authority)

**Goal:** A zero-dependency agent skill repository that builds lettered black-and-white manga pages as SVG from a declarative page file: code-built scenes plus VRM characters, inked by one engine, with region rework and self-checks.

**Architecture:** `kit/` holds pure modules: forms and distance-field raster, VRM loader and mesh raster, shading into shared buffers, ink tracing, page compose, lettering. `scripts/` holds CLIs (build, capture, sheet, check, rework, diff, fingerprint). `examples/` holds complete pages with committed output.

**Reference code:** Working throwaway probes are in `.superpowers/probe/` (git-ignored). They are the behavioural reference. Port their algorithms into the module layout below, clean them up, and remove their known flaws (global random state, duplicated shading chains, magic paths). Probe images there (`mangaka-page.png`, `mangaka-cast.png`, `mangaka-poses.png`, `ink-probe.png`) show the look to preserve.

| Probe file | What it holds |
|---|---|
| `sdf.mjs` | form primitives and operations, noise, `surf` |
| `render.mjs` | camera, distance-field raster with hit refinement, normals, shadow term, normal-aware ambient, grayscale PNG writer |
| `vrm.mjs` | PNG decoder, GLB/VRM loader, pose with root transform, mesh raster |
| `unified.mjs` | merged raster of forms and actors, shadow, ambient, tone per material |
| `shade.mjs` | storm sky with moon (`makeSky`) |
| `ink.mjs` | tone regions, blacks, scanline and streamline hatching, brush outlines, decals, strands |
| `lib.mjs` | panel SVG assembly with supersampling, captions, bubbles, sound effects, focus and speed line backgrounds, font embedding |
| `scene.mjs` | the knight scene (about 130 parts, decals) |
| `page4.mjs`, `posetest.mjs`, `cast.mjs` | page composition, poses, expressions |

## Global Constraints

- Node 20.10+, ESM `.mjs`, built-in modules only. No npm dependencies, no `node_modules`. `package.json` exists only for `"type": "module"` and the `test` script.
- English everywhere: code, docs, commit messages.
- Determinism: no `Math.random`, no `Date`, no locale-dependent output in anything that reaches an output file. All randomness comes from `kit/rng.mjs`, seeded by hashing stable keys (panel id, part name, layer, screen cell). The same inputs must give byte-identical SVG.
- Locality: ink in a screen region must not depend on a random sequence consumed elsewhere. Changing one part may change ink only where that part, its shadow or its occlusion reaches, plus a margin of one stroke length.
- Tests use `node:test` and `node:assert`. `node --test tests/` must pass at the end of every task. Chrome-dependent tests skip when Chrome is absent.
- Commits: small, imperative subject, no attribution trailers of any kind (no `Co-Authored-By`, no generated-by lines). Git identity is already configured; do not change it.
- `models/*.vrm` are CC0 files and must not be modified. Never add a model whose own VRM metadata does not say CC0.
- Original characters only in examples and docs. No named third-party characters, no reproduction of existing manga pages.
- SVG output: coordinates rounded to one decimal, one `<path>` per layer per panel where possible, under 2 MB per page.
- Exported function names and file paths listed in a task are the contract later tasks rely on. Do not rename them.
- Do not edit files under `docs/superpowers/` or `.superpowers/`.

### Task 1: Foundations: rng, png, forms, distance-field raster

**Files:** `package.json`, `kit/rng.mjs`, `kit/png.mjs`, `kit/sdf.mjs`, `kit/raster.mjs`, `tests/rng.test.mjs`, `tests/png.test.mjs`, `tests/sdf.test.mjs`, `tests/raster.test.mjs`

**Port from:** `.superpowers/probe/sdf.mjs`, `.superpowers/probe/render.mjs`, PNG decoder in `.superpowers/probe/vrm.mjs`.

1. `kit/rng.mjs` exports `hash32(...keys)` (FNV-1a over the keys joined with `|`, numbers stringified, returns uint32), `rng(seed)` (mulberry32, returns a function giving floats in [0,1)), `rngFor(...keys)` (= `rng(hash32(...keys))`), and `rand01(...keys)` (one float from the hash, no state).
2. `kit/png.mjs` exports `decodePNG(buffer)` → `{ w, h, px }` with RGBA `Uint8Array` (colour types 0, 2, 3, 4, 6; bit depth 8 and 16; throws `Error('interlaced PNG not supported')` on interlace), `encodeGray(w, h, float01Array)` and `encodeRGBA(w, h, uint8Array)` → `Buffer`.
3. `kit/sdf.mjs` exports the probe's primitives and operations under the same names (`sphere`, `ellipsoid`, `rcone`, `cyl`, `ccone`, `box`, `union`, `smin`, `sub`, `ssub`, `inter`, `round`, `shell`, `disp`, `raw`, `xform`, `squash`, `mirrorX`, `rotX`, `rotY`, `rotZ`, `mmul`, `mapply`, `noise3`, `fbm`, `surf`). Every returned form is a function `(x, y, z) => distance` carrying `.b` (bounding sphere `[cx, cy, cz, r]`), `.st` (safe step factor) and `.desc` (plain object `{ op, ...params, args: [child descs] }`). `raw(fn, bound, st, tag)` and the displacement function of `disp(form, fn, amp, st, tag)` take a required string `tag` that stands in for the closure in `.desc`. Export `hashForm(form)` → 8-char hex string from `hash32(JSON.stringify(form.desc))`. `noise3` must be a pure hash noise as in the probe.
4. `kit/sdf.mjs` also exports `part(name, mat, form, opts = {})` → `{ name, mat, sdf: form, hash: hashForm(form), ...opts }` and `scene()` → an object with `parts`, `decals`, and methods `add(name, mat, form, opts)` (returns the form), `rivet(form, from, dir, r)`, `hole(form, from, dir, r)`, `line(points, { w, ko })`, `lineOn(form, origins, dir, { w, ko })`, `poly(points, { closed, fill, stroke, sw })`, `strand(points, { thr })`. Decal object shapes are exactly those the probe `ink.mjs` consumes (`type: 'rivet' | 'hole' | 'line' | 'poly' | 'strand'`).
5. `kit/raster.mjs` exports `makeCam({ yaw, pitch, scale, cx, cy, W, H, target })`, `lightCam(dir, target, scale, size)`, `project(cam, p)`, `rasterSDF(parts, cam, wantPos = true)` → `{ id, depth, pos, W, H }` (id is 1-based index into `parts`, 0 for empty; includes the probe's hit refinement), `normalsSDF(parts, cam, buf)` → `{ nx, ny, nz, wn }`, `shadowTerm(buf, lightCam, lightBuf, bias)`, `ambient(buf, nrm, scale, radiusPx, samples, far)` (the normal-aware version).
6. Tests: `hash32` is stable across runs and differs for different key order; `rng` sequences repeat for equal seeds; PNG encode then decode round-trips a gradient; each primitive is negative at its centre and positive far away, and `surf` samples from 64 directions all lie inside `.b`; `hashForm` is equal for equal construction and changes when one number changes; rastering a sphere of radius 0.5 at scale 200 gives a pixel count within 2% of `π·100²`, centre depth equals the near surface, centre normal has `nz > 0.99`.

### Task 2: VRM actors: loader, pose, mesh raster, pose library

**Files:** `kit/vrm.mjs`, `kit/mesh.mjs`, `kit/poses.mjs`, `models/README.md`, `tests/vrm.test.mjs`, `tests/mesh.test.mjs`, `tests/poses.test.mjs`

**Port from:** `.superpowers/probe/vrm.mjs`, `.superpowers/probe/posetest.mjs`, `.superpowers/probe/page4.mjs`.

1. `kit/vrm.mjs` exports `loadVRM(path)` and `poseVRM(model, { pose = {}, expr = {}, root = null, flip = true })` → `{ posed, bonePos }` with the probe's behaviour (morph targets before skinning, linear blend skinning, 180° flip so the model faces +Z, root `{ pos, yaw }`). It uses `decodePNG` from `kit/png.mjs`. A file with `extensions.VRMC_vrm` (VRM 1.0) throws `Error('VRM 1.0 is not supported yet; export as VRM 0.x')`. A file without `extensions.VRM` throws `Error('not a VRM file')`. `model.meta` exposes the VRM meta block. Material classes are `skin`, `hair`, `cloth`, `tex` as in the probe, with a fallback of `cloth` for unknown names that have no `_FACE`/`_EYE` marker.
2. `kit/vrm.mjs` exports `partNamer(actorName)` → a function `(prim, mat) => name` giving stable part names: `<actor>.skin` for all skin, `<actor>.hair.<index>` per hair primitive, `<actor>.<short material name>` otherwise, where the short name strips the `F00_000_00_`-style prefix and the trailing class suffix.
3. `kit/mesh.mjs` exports `rasterMesh(model, posed, cam, idOf, wantColor = true)` → `{ id, depth, pos, wn, lum, W, H }` with alpha cut-out and the render-queue depth bias from the probe. `idOf(prim, mat)` returns a 1-based id or 0 to skip.
4. `kit/poses.mjs` exports `HANDS` (`open`, `relaxed`, `fist`, `point`, `grip`), `POSES` (`tpose`, `stand`, `relaxed`, `guard`, `reach`, `walk`, `run`, `sit`), `withHands(pose, { left, right })`, `mirrorPose(pose)` (swaps left and right and negates Y and Z rotations), `mixPose(a, b, t)`. Poses are plain objects of bone name → `[x, y, z]` Euler radians. Start from the values in the probe (`stand`, `fist`, `curl`) and derive the rest; verify each by rendering a debug PNG with `encodeGray` and looking at it.
5. `models/README.md` lists each bundled file with title, source repository (`github.com/madjin/vrm-samples`, folder `vroid/beta`), and the licence fields read from the file's own metadata.
6. Tests (use `models/fumiriya.vrm`): loads, `meta.licenseName === 'CC0'`, at least 50 humanoid bones; posing `POSES.stand` puts `bonePos.leftHand[1]` below `bonePos.leftUpperArm[1]`; `expr: { a: 1 }` changes vertex positions of at least one face primitive; `rasterMesh` at a head close-up yields at least 5 distinct ids and no id on the image border when the head is centred; rastering twice gives identical buffers; VRM 1.0 and non-VRM errors are thrown for crafted minimal GLBs.

### Task 3: Shading, ink, styles: deterministic and local

**Files:** `kit/materials.mjs`, `kit/backgrounds.mjs`, `kit/shade.mjs`, `kit/ink.mjs`, `kit/styles.mjs`, `tests/shade.test.mjs`, `tests/ink.test.mjs`, `tests/styles.test.mjs`

**Port from:** `.superpowers/probe/unified.mjs`, `.superpowers/probe/shade.mjs` (`makeSky`), `.superpowers/probe/ink.mjs`, backgrounds in `.superpowers/probe/lib.mjs` (`focusSky`, `speedSky`).

1. `kit/materials.mjs` exports `toneOf(mat, ctx)` → tone 0 (white) to 1 (black) and optionally sets `ctx.aux`, one function per material replacing the probe's if-chains: `metal`, `metalD`, `cloth`, `hair`, `leather`, `wood`, `mail`, `stone`, `ground` for forms; `skin`, `hairB` (with `hair: 'black' | 'light'`), `fabric`, `tex` for actors. `ctx` carries `lam`, `fill`, `rim`, `ao`, `spec`, `lum`, `wy`, `skinMean`, `hairMean`.
2. `kit/backgrounds.mjs` exports pure functions returning `(x, y, W, H) => tone`: `flat(v)`, `gradient(top, bottom)`, `split(xFrac, left, right)`, `storm({ moon: [x, y, r] | null, seed })`, `focusLines({ cx, cy, r0, count, density, seed })`, `speedLines({ angle, density, pitch, seed })`. Coordinates are in panel pixels before supersampling; each takes an `ss` factor through `scaled(fn, ss)`.
3. `kit/shade.mjs` exports `renderPanel({ scene = null, actors = [], cam, background, light = {}, fill, aoRadius, skinDetail, shineAt })` → `{ cam, buf, nrm, D, aux, W, H, parts, decals }`. `scene` is `{ parts, decals }` from `kit/sdf.mjs`; each actor is `{ name, model, posed, hair }`. Forms and actors share one z-buffer and one shadow map. `parts` is the merged list (`{ name, mat, cls? }`), ids in `buf.id` index it 1-based.
4. `kit/ink.mjs` exports `inkPanel(r, { style, seed, regions = [] })` → `{ tone1, tone2, blacks, hatch: [thin, mid, core], mail, dots, brush, decals: { ko, lines, shapes, strandsWhite, strandsBlack, rivets, holes } }`, each an array of individual SVG path strings (or shape objects as in the probe) in panel buffer pixels. `seed` is a string (the panel id).
5. The probe's global `rnd()` must go. Rules: scanline hatching derives each line's spacing jitter from `rand01(seed, 'scan', layer, kind, lineIndex)` on a fixed lattice, and each stroke's threshold, length and wobble from `rand01(seed, 'scan', layer, kind, lineIndex, startCell)`; streamline hatching derives one seed point, threshold and length per grid cell from `rand01(seed, 'stream', layer, cellX, cellY, n)` and visits cells in a fixed order sorted by `hash32(seed, layer, cellX, cellY)`; brush outlines derive their wobble phase from the chain's first corner; dots and mail use per-cell hashes. Part angles for `fix` fields come from `rand01(seed, 'ang', partName)`.
6. `kit/styles.mjs` exports `STYLES` with `seinen-dense` (no tone on forms, tone on actors' skin, fabric and face layers, three hatch layers), `shonen-clean` (tone on sky, cloth, skin, fabric, face layers; hatching only on metal, stone, ground) and `tone-soft` (tone wherever possible, at most one hatch layer), and `resolveStyle(nameOrObject, overrides)`. A style holds: `black`, `tone1`, `tone2`, `toneMats`, per-material `{ fields, thresholds, len, crease }`, `brush` weights for the three line classes, `hatchSpacing`, `depthK`.
7. `regions` are `{ rect: [x, y, w, h], feather, set: { black?, tone1?, tone2?, hatch?, brush? } }` in panel pixels. Inside a region the listed thresholds are replaced per pixel (blended across `feather`); `hatch` multiplies hatch density, `brush` multiplies line weight.
8. Tests: `inkPanel` twice on the same input is deep-equal; locality: a scene with two spheres 400 px apart, change the radius of the left one, and every path whose bounding box lies entirely in the right third is present unchanged in both results (compare as string sets per layer); switching style changes at least one layer; a region override changes only paths whose bounding box intersects the region grown by 40 px; `renderPanel` with one form and one actor gives ids from both and a shadow of the actor on the form (tone under the actor's feet darker than beside it).

### Task 4: Page, lettering, effects, build CLI, first example

**Files:** `kit/page.mjs`, `kit/lettering.mjs`, `kit/effects.mjs`, `kit/fonts/` (copy the two `.woff` and two `.woff2` files and both licences from `.superpowers/probe/fonts/`), `scripts/build.mjs`, `examples/gate/knight.mjs`, `examples/gate/page.mjs`, `examples/gate/page.svg`, `examples/gate/page.html`, `examples/gate/page.map.json`, `examples/gate/page.stats.json`, `tests/page.test.mjs`, `tests/lettering.test.mjs`

**Port from:** `.superpowers/probe/lib.mjs`, `.superpowers/probe/page4.mjs`, `.superpowers/probe/scene.mjs`.

1. `kit/page.mjs` exports `definePage(spec)` (validates and returns the spec; errors name the panel id and field) and `buildPage(spec, { dir, cacheDir = null })` → `{ svg, html, map, stats }`, also written to `dir` as `page.svg`, `page.html`, `page.map.json`, `page.stats.json`. Spec shape: `{ size: [w, h], reading: 'rtl' | 'ltr', style, panels: [{ id, rect: [x, y, w, h], ss = 1, scene, actors: [{ name, model, pose, expr, root, hair }], camera: { yaw, pitch, scale, target, cx?, cy? } | (ctx) => camera, background, light, style?, regions?, effects?, frame = 4.5, gutter = 0, inset = false }], lettering: [...] }`. A camera function receives `{ bones: { [actor]: bonePos } }` so a shot can target a bone. `model` is a path resolved relative to the page file or a loaded model.
2. Panel SVG assembly follows the probe's `panel()` including supersampling (`ss`), clip path, per-panel tone patterns and layer order: tone1, tone2, blacks, hatch, mail, dots, brush, knock-outs, lines, strands, shapes, rivets, holes, effects, frame. Panel ids prefix all SVG ids.
3. `kit/lettering.mjs` exports `fontMetrics(woffBuffer)` (parses `cmap`, `hmtx`, `head`, `hhea` from a WOFF 1 file with `node:zlib`) and `measure(text, font, size)`, `wrap(text, font, size, maxWidth)`, `caption({ text, at, width })`, `bubble({ kind: 'speech' | 'thought' | 'shout' | 'whisper', text, at, tail })`, `sfx({ text, at, rotate, size })`. A bubble sizes its ellipse to the wrapped text. `tail` is a point or `{ actor, bone }` resolved through the panel camera. `shout` has a spiked outline, `whisper` a dashed outline, `thought` a cloud outline with trailing circles. Fonts are embedded once per page as base64 WOFF2.
4. `kit/effects.mjs` exports `rain({ density, angle, seed })`, `snow({ density, seed })`, `spatter({ at, count, radius, seed })`, each returning SVG path data in panel pixels, deterministic.
5. `page.map.json`: `{ size, panels: [{ id, rect, ss, camera, parts: [names], rle: [...] }] }` where `rle` run-length encodes the part-id buffer downsampled to half resolution (pairs of id and run length, row-major). `page.stats.json`: per panel the share of black, tone and white pixels, stroke counts per layer, and the page SVG byte size.
6. `scripts/build.mjs <page.mjs> [--no-cache]` imports the default export of the page file, builds it next to the file and prints one line per panel with its time.
7. `examples/gate/knight.mjs` is the probe's knight scene ported to `scene()` and `part` names in dotted form (`knight.helm.band`). `examples/gate/page.mjs` recreates the probe page (`mangaka-page.png`): opening panel with the knight and the boy from `models/fumiriya.vrm` in one scene under a storm sky with rain, a surprised close-up on focus lines, a fist on speed lines, a determined close-up with an inset of the knight's helm, two captions, two bubbles, two sound effects. Commit its four output files.
8. Tests: `buildPage` twice gives identical `svg`; the map's `rle` decodes to the right pixel count; `wrap` never exceeds `maxWidth`; a bubble's ellipse contains every wrapped line's box; `definePage` rejects a panel without `rect` naming its id.

### Task 5: Verification scripts

**Files:** `scripts/chrome.mjs`, `scripts/capture.mjs`, `scripts/sheet.mjs`, `scripts/check.mjs`, `scripts/fingerprint.mjs`, `tests/check.test.mjs`, `tests/capture.test.mjs`

1. `scripts/chrome.mjs` exports `findChrome()` (honours `CHROME_PATH`, then usual locations on Linux, macOS, Windows) and `screenshot({ url, out, width, height, scale = 1 })` using Chrome's `--headless=new --screenshot` flags with `--no-sandbox --disable-gpu --hide-scrollbars`.
2. `scripts/capture.mjs <dir> [--panel id] [--part name] [--zoom 2|4] [--grid n] --out shots/` screenshots the page, single panels, a part's bounding box (from the map) or a grid of close-ups, by writing a small wrapper HTML that offsets and scales `page.svg`.
3. `scripts/sheet.mjs <dir> --out shots/sheet.png` builds one contact sheet: the full page plus a 3×2 grid of 3× close-ups chosen as the six panel regions with the highest stroke density.
4. `scripts/check.mjs <dir>` reads `page.stats.json`, `page.map.json` and `page.svg` and exits 1 with a list when: a panel's black share is outside the style's range, a panel is over 97% white or black, the SVG is over 2 MB, a lettering box leaves its panel or the page, bubbles in a panel are out of reading order, or a rebuild's fingerprint differs.
5. `scripts/fingerprint.mjs <page.mjs>` builds twice without cache and compares SHA-256 of the SVG.
6. Tests: `check` logic on crafted stats and maps (pass and each failure); capture test runs only when Chrome is found and asserts a PNG signature.

### Task 6: Region rework

**Files:** `kit/viewer.mjs`, `kit/viewer-core.mjs`, `kit/page.mjs` (cache and viewer wiring), `scripts/rework.mjs`, `scripts/diff.mjs`, `tests/viewer.test.mjs`, `tests/rework.test.mjs`

1. `kit/viewer-core.mjs` exports pure functions shared by Node and the browser: `decodeRle(panel)`, `partsInRect(map, pageRect)` → `{ panel, region, parts: [{ name, share }] }` and `formatInstruction({ pageFile, panel, region, parts, request })` producing exactly the block shown in spec section 4.6.
2. `kit/viewer.mjs` exports `viewerHtml({ svg, map, pageFile })`: the page, a toolbar with an edit toggle, drag-to-select on the page, a text field for the request, a preview of the instruction and a copy button. It inlines `viewer-core.mjs` source. No external resources.
3. `buildPage` gains a cache: each panel's SVG fragment and stats are stored under `cacheDir/<panel id>-<hash>.json`, the hash covering form hashes, actor model path, pose, expression, root, camera, background description, light, style, regions and `ss`. Unchanged panels are reused.
4. `scripts/rework.mjs <page.mjs> --panel id` saves the current `page.svg` as `page.prev.svg`, rebuilds with the cache and prints which panels were rebuilt.
5. `scripts/diff.mjs <dir> --panel id --region x,y,w,h [--margin 40]` splits both SVGs into panels and layers, compares path strings as sets, and exits 1 listing layers with changed paths whose bounding box lies outside the region grown by the margin. `--allow-part name` widens the allowed area to that part's bounding box and shadow from the map.
6. Tests: `partsInRect` on a crafted map; `formatInstruction` snapshot; cache reuses untouched panels (assert by build log); `diff` passes for a region override and fails when a second, far region is also changed.
